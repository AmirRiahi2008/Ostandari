# اتصال و رفتار صفحه‌ها

## دو حالت اجرا

در `TEMPLATE_PREVIEW=true` قالب‌های ارسالی و صفحه‌های تکمیلی بدون وابستگی به دیتابیس نمایش داده می‌شوند. مدیریت با حساب محلی `admin/admin` باز می‌شود. نشست محلی امضاشده و HttpOnly است؛ کلید آن در زمان اجرا تولید می‌شود و در ZIP وجود ندارد. عملیات نوشتن مدیریت در این حالت ثبت ساختگی انجام نمی‌دهند.

در `TEMPLATE_PREVIEW=false` ورود، فهرست‌ها، ثبت و ویرایش از Laravel استفاده می‌کنند. پراکسی Next توکن Laravel را در کوکی HttpOnly نگه می‌دارد. نام دیتابیس، رمز MySQL و نشانی داخلی API به فرم‌های سایت وارد نمی‌شوند.

## نقشه و فرمانداری

`src/data/counties.ts` نام، slug و اتصال هندسهٔ هر ناحیه را نگه می‌دارد. هندسه از فایل اصلی طراحی استخراج شده است. لینک‌ها و برچسب‌ها از همان داده ساخته می‌شوند؛ کنترلر جاوااسکریپت، مقصد را به شمارهٔ ناحیه تغییر نمی‌دهد.

`OfficePage` و `PortalLayout` قالب مشترک تمام شهرستان‌ها هستند. شهر نامعتبر ۴۰۴ می‌گیرد. نبود اطلاعات، وضعیت خالیِ همان بخش را نشان می‌دهد. مسئول فعلی از اعضای همان شهرستان با نوع `county_governor` انتخاب می‌شود. خبر و گالری با واحد فرمانداری فیلتر می‌شوند.

برای نمایش اطلاعات واقعی یک فرمانداری، در مدیریت به رکورد شهرستان، واحد سازمانی، عضو مسئول فعلی، اخبار و گالری مربوط داده بدهید. Seeder پایه فقط نام شهرستان‌ها و واحدها را ایجاد می‌کند.

## مقصدها و فرم‌های عمومی

اخبار فهرست و جزئیات جدا دارد. کارت‌ها پیوند عادی HTML دارند و برای کلیک به یک handler روی `div` وابسته نیستند. صفحه‌های قوانین، اطلاعات، مدیران، رویدادها و فراخوان‌ها در تم سایت ساخته شده‌اند؛ محتوای واقعی آن‌ها از API می‌آید.

فرم‌های تماس، عضویت و تأیید خبرنامه، بازیابی رمز، دیدگاه و نظرسنجی به مسیرهای API مرتبط متصل‌اند. نظرسنجی و دیدگاه به ورود Laravel نیاز دارند. اگر سرویس محلی خاموش باشد، پیام خطا نشان داده می‌شود و تأیید موفق ساخته نمی‌شود. پیام تماس فرمانداری با `county_slug` به واحد همان شهرستان می‌رود.

در محیط محلی با mail driver از نوع `log`، لینک تکمیل خبرنامه و بازیابی رمز با dev token برگشتی API نمایش داده می‌شود. در محیط واقعی این توکن از پاسخ عمومی حذف می‌شود. ورود Google در طرح وجود داشت، اما سرویس OAuth برای آن پیکربندی نشده است؛ دکمه، این وضعیت را توضیح می‌دهد.

## مدیریت

فرم‌های مدیریت از قرارداد فیلدهای Laravel ساخته می‌شوند. فهرست اعضا به `members` و فهرست فرم‌ها به `forms` متصل است. پیام‌ها، بررسی فرم‌ها، نظرات، مشترکان و تنظیمات از مسیرهای اختصاصی خود استفاده می‌کنند. فیلدهای آرایه‌ای مانند schema فرم و دسترسی نقش، JSON معتبر می‌گیرند و پیش از ارسال بررسی می‌شوند.

مسیرهای تکمیلی `/admin/news`، `/admin/pages`، `/admin/counties`، `/admin/services`، `/admin/galleries`، `/admin/gallery-items` و `/admin/poll-options` با اجزای پنل اصلی ساخته شده‌اند.

تغییر وضعیت پیام‌ها همچنان به قواعد Laravel وابسته است. گزارش‌های شهروند و پیوست‌ها کنترل مالکیت بک‌اند را حفظ می‌کنند. درخواست‌های ارسال‌شده در حساب کاربر از داشبورد شهروند قابل پیگیری‌اند؛ پیام تماس بدون ورود، در مدیریت با شناسهٔ خودش بررسی می‌شود.

## بررسی و محتوا

محتوای نمونه از فایل‌های ارسالی است؛ خبر یا مشخصات مسئول جاری محسوب نمی‌شود. نشانی نهایی سرویس‌ها، اطلاعات رسمی هر فرمانداری، شبکه‌های اجتماعی و متن سیاست‌ها باید در CMS ثبت شوند. سایت برای دادهٔ غایب، اطلاعات یک سازمان دیگر را جایگزین نمی‌کند.

تست‌های خودکار، مقصدهای داخلی، فایل‌ها، ساختار SVG، فرم‌ها، نشست و API را پوشش می‌دهند. بررسی تصویریِ نسخهٔ محلی در مرورگر انجام نشده است؛ حدود این بررسی در `VERIFICATION.md` آمده است.
